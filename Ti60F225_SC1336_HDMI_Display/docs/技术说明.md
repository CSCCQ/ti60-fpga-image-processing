# 系统设计与算法

## 图像通路

SC1336 摄像头的数据经 MIPI 接收、RAW/Bayer 转 RGB、裁剪和 DDR 缓存，进入显示处理流水线。FPGA 完成灰度变换、中值与高斯滤波、Sobel 与 Canny 边缘检测、图形识别和字符叠加；RV32 SapphireSoC 配合 TinyML 卷积加速器完成数字分类。

我把连续的视频显示和数字分类分开处理：显示端按固定 HDMI 时序输出，处理器通过二值快照读取识别输入，再通过结果寄存器更新框和标签。这样数字分类所需的时间不会打断视频输出。

两种边缘算法共享滑动窗口和缓存。DDR 保存原始帧，回放时重新经过当前选择的处理通路，所以同一张保存帧可以调整阈值、切换算法和进行识别。按键消抖、单击、多击和长按判定均在硬件中完成。

## 数字定位与分类

我使用 Calibri Bold 印刷数字制作训练样本，并加入缩放、轻微旋转、透视、模糊、弯曲和断边变化。类别包含 0～9，以及用于排除非数字区域的拒识类别。

FPGA 对二值边缘进行 4×4 OR 池化，得到 320×180 的单比特快照。CPU 通过连通域寻找候选区域，将候选图像按比例归一化到 32×32，再送入 INT8 CNN。分类后，把候选框映射回 1280×720 坐标，最多显示 16 个框及对应数字。

早期实现中，分类结果更新速度会影响框的跟随。为改善这一点，工程将取图与处理重叠，并使用输入缓存、轮廓匹配、有限期标签复用和批量结果更新，减少重复推理和框的闪烁。

模型共有 17,411 个参数，TFLite 文件为 22,064 字节。在独立的 3,300 张合成测试图上，分类准确率为 99.39%。当前适用对象是基本正立、相互分离、在画面中足够大的指定印刷数字。其他字体、严重遮挡、过曝或失焦，以及大幅旋转后的 6 和 9，仍需要扩大数据集和实拍测试。

## 低阈值噪声处理

低阈值会把摄像头的微小亮度波动也识别为边缘，过曝和失焦区域尤其明显。我采用较保守的筛选方式，尽量保留数字笔画和真实轮廓：

- 高斯 Canny 在 TH 为 20、30、40 时，对同一行亮度差不超过 12 的相邻处理值作有界平均，并把两位高斯小数保留到梯度计算之后。
- 结合邻域方向和支持度筛掉孤立响应。
- 两种全屏二值模式在 TH 小于 160 时，用上一帧的 4×4 块占用情况确认弱边缘，较强边缘直接通过。
- 屏蔽画面最外侧约 8 像素的无效卷积边界，消除屏幕四周持续出现的白线。

中值 Sobel 不经过上述灰度平均，高斯 Canny 在 TH 大于等于 50 时也绕过这一步及相应精度处理。红边模式的图形识别使用原来的边缘通路，避免降噪筛选破坏轮廓。

这套处理没有增加整帧视频缓存延迟，但新出现的弱边缘可能需要等下一帧确认。目前能够减少部分闪烁，过曝和失焦产生的噪点还不能完全消除。

## 测试结果

| 项目 | 结果 |
|---|---|
| HDMI 输出 | 1280×720，60 Hz |
| XLR | 60,716 / 60,800 |
| RAM | 256 / 256 |
| DSP | 38 / 160 |
| 时序报告 | 检查 274 条路径，最小 slack 0.018 ns，无负 slack |
| 数字模型分类 | 独立合成测试集 3,300 张，准确率 99.39% |
| 降噪前后数字回归 | 160 组场景中，两版均有 139 组全部识别正确，未新增识别丢失或错误标签 |

屏幕 FPS 根据显示输出帧计数计算，表示 HDMI 刷新情况。数字识别速度取决于候选数量、缓存命中和推理耗时，不能用这个 FPS 代替。

板上测试覆盖七种显示模式、模式循环切换、两种二值模式下的数字识别、红边图形识别、阈值调整、冻结保存、回放和自动启动。Flash 写入后进行了回读校验，并通过断电再上电检查原图颜色和数字识别进出。对应记录见 [测试记录](verification/README.md)。
